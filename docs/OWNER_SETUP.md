# Owner setup

Nothing here has run on GitHub yet. In order:

1. Create the empty public repository `nodemode-dev/formadaptor`. Push `main` once, then push `feat/first-build-0.1.0` and open its pull request. Merge with a merge commit (no squash) so each commit and its signature stay.
2. Settings, Actions, General: allow GitHub Actions; Workflow permissions "Read repository contents" (the workflows widen it per job). Do not allow Actions to create or approve pull requests here; formadaptor opens none; formcompiler's `adaptor.yml` opens them in the targets.
3. formadaptor holds no secret: add none here, and create no App for it. Proposing is formcompiler's `adaptor.yml`, which signs in with formcompiler's release App from formcompiler's `release` environment. Its plan job runs each target's generator with `scripts/propose.py plan` and holds no secret and no environment; its apply job holds the token, runs no target code, and re-checks every planned file with `scripts/propose.py apply`.
4. On formcompiler's release App: add the Repository permission "Pull requests: read and write" beside Contents, and install it on each target repository in targets.json: formMCP, formskills, form.ext and formai-templates (step 11) now; .github when the profile target is switched on (step 6). Not on formtray: it is not a target (its app list is your dated release schedule, kept by hand). Each run mints a token for one target repository at a time.
5. In each target: if `main` has a ruleset, make sure it does not stop that App from pushing `bot/*` branches (a branch ruleset that restricts creation must list the App as a bypass actor for `bot/**`). Pull requests opened with the App token start the target's checks, unlike those opened with the built-in token.
6. Merge the target changes (docs/TARGETS.md) in formMCP, formskills and form.ext, each with its generated files regenerated from the current spec and its copy of that spec committed beside them (`setup/family.spec.json` in all three), so the first proposal finds nothing to change. The profile target (.github) is disabled in `targets.json`: it is switched on when the page's listing rule is chosen. The page lists apps whose registry `state` is `live`; six apps formai.studio shows as live are `public` or `prelaunch` in the registry, so decide first which is right (fix the registry's `catalog.state`, or change the page's listing rule in .github), make .github's generator write its copy at `scripts/family.spec.json`, regenerate the page, then set `"enabled": true` for `profile` here and install the App on .github.
7. Run `hourly` by hand once (Actions, hourly, Run workflow). It creates the `spec` branch with `family.json`. Then run formcompiler's `adaptor` by hand to see every enabled target answer "in step".
8. form.ext is enabled here with the three files its generator writes (`.claude/skills/HOSTS.md`, `setup/hosts.json`, `setup/family.spec.json`); its generator must be on form.ext's `main` before the first run, or that one job fails (the others go on). The hourly summary's advisory section names apps whose `main` offers agents something their newest release does not; it never fails the run and needs nothing from you except, when you want it, a release.
9. formai.studio is private: the App needs access there for a site target, or the site's own CI runs the generator's `--check` against `family.json`. Not configured in 0.1.0.
10. In formcompiler's `formai-build` list of repositories it does not build, add formadaptor (it is not an app and has no registry entry).
11. formai-templates (since 0.2.0): create the empty public repository `nodemode-dev/formai-templates` and push its `main` from the local build (no squash). Add it to the installation of formcompiler's release App (Settings of the App, Install App, `nodemode-dev`, the selected repositories); no new secret, the same App mints its token, for that one repository. Step 5 applies to it as to the others. Until it exists and the App is installed, its job in `adaptor.yml` is a skip with one line in the summary and nothing fails. The apps' own repositories need nothing: formadaptor clones the public ones at their released tags with no token.
